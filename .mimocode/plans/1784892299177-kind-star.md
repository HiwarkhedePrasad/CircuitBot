# Fix: NE555 Pipeline — 3 Bugs Causing Complete Failure

## Bug Chain

```
Bug 1: NE555D selected instead of NE555P (wrong package)
  → Bug 2: Dependency expander injects 0 support components
    → Bug 3: Validator frozen, can't add missing components
      → Pipeline produces incomplete circuit
```

## Bug 1: Wrong Package Selected (NE555D vs NE555P)

**File:** `agent/nodes/select.py` lines 616-625

**Problem:** Substring match `if p in cid` picks the first NE555 variant (NE555D/SOIC-8) regardless of user's "through-hole" constraint.

**Fix:** Add package-type awareness to user-requested part promotion:
```python
# After finding substring matches, filter by package preference
through_hole = any(kw in prompt.lower() for kw in ("through-hole", "through hole", "dip", "dip-8", "pdip"))
if through_hole:
    # Prefer DIP/through-hole variants
    for idx in candidates_matching:
        cid = candidates[idx].get("id_str", "")
        if any(pkg in cid.upper() for pkg in ("P", "DIP", "PDIP")):
            found_idx = idx
            break
```

## Bug 2: Dependency Expander Injects 0 Components

**Root causes (3 sub-issues):**

### 2a: Missing `compatible` fields in dependency_graph.py

**File:** `agent/knowledge/dependency_graph.py` lines 156-167

**Problem:** NE555 requirements have no `compatible` fields, so `preferred_id_str` is empty, and the fallback path is skipped.

**Fix:** Add `compatible` and `preferred_id_str` to each requirement:
```python
"NE555": {
    "requires": {
        "timing_resistor_ra": {
            "required": True,
            "note": "10k resistor between VCC and DISCH pin",
            "compatible": ["Device:R", "Device:R_Small"],
            "preferred_id_str": "Device:R_Small",
            "value": "10k",
        },
        # ... same for rb, ct, bypass, current_limit
    },
}
```

### 2b: Overly aggressive `already_present` check

**File:** `agent/nodes/dependency_expander.py` lines 261-272

**Problem:** 2-word substring match falsely marks requirements as "already satisfied".

**Fix:** Increase threshold to 3+ words OR use structured matching:
```python
# Require 3+ word matches OR exact category+value match
if match_count >= 3 or (match_count >= 2 and has_value_match):
    already_present = True
```

### 2c: Fallback skipped when preferred_id_str is empty

**File:** `agent/nodes/dependency_expander.py` lines 127-134

**Problem:** When `preferred` is empty, the fallback that creates a component from a known ID is never reached.

**Fix:** When `preferred` is empty but `compatible` list exists, use the first compatible ID:
```python
if not preferred and compatible:
    preferred = compatible[0]
```

## Bug 3: Validator Frozen, Can't Add Missing Components

**File:** `agent/nodes/validate.py` lines 868-876

**Problem:** When architecture is frozen, validator reports "5 missing components NOT auto-added" instead of injecting them.

**Fix:** Allow validator to inject support components for known-requirement ICs even when frozen:
```python
if missing and state.get("architecture_frozen"):
    # Exception: inject support components for known-requirement ICs
    from agent.knowledge.dependency_graph import get_requirements
    from agent.knowledge.component_catalog import resolve_component
    injectable = []
    for mc in missing:
        resolved = resolve_component(mc.get("requirement_id", ""), mc.get("description", ""))
        if resolved:
            injectable.append(resolved)
            _emit(config, "agent:log", {
                "message": f"  Auto-injecting support component: {resolved['id_str']}"
            })
    if injectable:
        missing = []  # Clear so auto-add block runs with injectable list
    else:
        # Truly unresolvable — keep as errors
        for mc in missing:
            validation_errors.append(f"Missing component: {mc.get('description', '')}")
        missing = []
```
