## PART 1: Architecture Overview

CircuitBot's PCB system is a **full-stack PCB design tool** with:

- **Backend**: Python (Flask + SocketIO) with LangGraph agent pipeline, PCB design algorithms, KiCad import/export
- **Frontend**: Dual-path rendering (WebGL2 primary + Canvas2D fallback) with 12 modular JS files in `static/pcb_view/`
- **Data model**: `BoardModel` as the single source of truth, exchanged as JSON between backend and frontend

## PART 3: Rendering Pipeline (Frontend)

### 3.1 Dual-Path Architecture

```
PcbEditorWebGL.refresh()
  ├─ 1. Grid (WebGL shader on full-screen quad)
  │    Fragment shader: procedural 1.27mm minor / 6.35mm major grid + origin axes
  │
  ├─ 2. Board Content (primary path selection):
  │    IF KiCanvas WebGL2 available:
  │    │  _renderKiCanvasContent()
  │    │  └─ BoardPainter.paint():
  │    │       ├─ _paintBoardOutline()  — Edge.Cuts polygon fill + edge line
  │    │       ├─ _paintTraces()        — sorted bottom-first, r.line(path, width, color)
  │    │       ├─ _paintVias()          — r.circle(center, radius, color)
  │    │       └─ _paintComponents()    — body fill → pads (mask, copper, drills) → graphics
  │    │
  │    ELSE (Canvas2D fallback):
  │    │  _drawBoardCanvas(ctx, model)
  │    │    Pass 1: Component body fills
  │    │    Pass 2: Copper traces (bottom first, then front)
  │    │    Pass 3: Vias (4-layer: copper ring + highlight + drill + shadow)
  │    │    Pass 4: Solder mask expansions
  │    │    Pass 5: Copper pads (SMD=red/blue, THT=golden)
  │    │    Pass 6: Drill holes (dark circles)
  │    │    Pass 7: Graphics (SilkS, Fab, CrtYd)
  │
  └─ 3. Overlay (always Canvas2D on #pcbOverlayCanvas, z-index:3, pointer-events:none):
       ├─ Airwires (redirected during active routing)
       ├─ Active route ghost path (#fff1a8, yellow-white)
       ├─ Route cursor crosshair + info tooltip (net name + length)
       ├─ Pad attraction glow during routing
       ├─ Trace selection/hover highlights (red/green overlay)
       ├─ Net highlighting (cyan glow)
       ├─ Ghost component for AI proposals
       ├─ Constraint violation icons (!)
       ├─ Board outline preview
       ├─ Selection boxes
       └─ Comments
```

### 3.2 Camera System

- Effective scale = `baseScale * zoom`
- View matrix: translate(center+pan) → scale(s, -s) → translate(-midX, -midY)
- Projection: orthographic pixel-to-clip-space
- `screenToWorld(sx, sy)` and `worldToScreen(wx, wy)` convert between coordinate systems
- KiCanvas `Camera2` synced for WebGL2 renderer path

### 3.3 Hit Testing

| Method | Strategy |
|--------|----------|
| `hitTestPad(sx, sy)` | AABB with zoom-scaled tolerance on all component pads |
| `hitTestTrace(sx, sy)` | Reverse iteration, point-to-segment projection, distance ≤ width/2 + 0.1mm |
| `hitTestVia(sx, sy)` | Reverse iteration, Euclidean distance ≤ via radius + 0.1mm |
| `hitTestComponent(sx, sy)` | Bounding box check via `getComponentBounds()` |

## PART 4: Trace Routing (Complete Data Flow)

### 4.1 Manual Routing (Frontend)

**State variables** (state.js):
```
routeStartAnchor: {kind, key, x, y, noSnap}  — pad/trace hit where routing began
routeNetName: string                          — resolved from pad's net
routeLayer: 'F.Cu' | 'B.Cu'                  — current routing layer
routeWidth: 0.254                             — trace width in mm
routePoints: [{x,y}, ...]                     — accumulated waypoints (grid-snapped)
routeVias: [{x,y,drill,diameter,layers,net}] — vias placed during this route
routeCursor: {x,y} | null                     — live cursor position
```

**Route lifecycle**:

1. **Start** (`beginRoute(anchor)` in utils.js:403-431):
   - Resolves net name via `getNetNameForPad()`
   - Sets route layer from pad's layer membership
   - Initializes `routePoints = [snappedAnchor]`
   - Auto-inserts via if anchor layer differs from route layer
   - Sets `mode = PCB_MODE.ROUTE`

2. **Continue** (`pcbHandleMouseMove` in events.js:543-564):
   - Converts screen→world with grid snapping (0.254mm)
   - **Axis-locking**: within 0.6mm of prev point on one axis → locks H or V
   - Hit-tests pads/traces for snap-to-target
   - Updates `routeCursor` → triggers overlay refresh

3. **Waypoint** (click during routing, events.js:416-419):
   - `appendRoutePoint(routePoints, routeCursor)` — grid-snapped, deduped

4. **Via insertion** (V key, events.js:2143-2157):
   - Creates via at `routeCursor` position
   - Pushes to `routeVias[]`
   - Appends cursor to `routePoints`
   - Toggles `routeLayer` (F.Cu ↔ B.Cu)

5. **Complete** (`commitRouteToBoard(targetPad)` in events.js:239-290):
   - Deep-clones board model (for undo)
   - Finalizes path via `dedupePath(appendRoutePoint(routePoints, targetPad))`
   - Creates trace object: `{net, layer, width, path}`
   - Pushes trace to `boardModel.traces[]`
   - Pushes all `routeVias[]` to `boardModel.vias[]`
   - Auto-via at endpoint if layer mismatches pad
   - Recomputes ratsnest client-side
   - Saves to backend via `POST /api/save_board_model`
   - Pushes to undo history
   - Triggers constraint check

6. **Cancel** (`pcbCancelDraw()` in events.js:193-206):
   - Resets all route state to defaults
   - Sets mode to IDLE

### 4.2 Backend Autorouter (router2.py)

**Algorithm**: Weighted A* maze routing with rip-up & reroute

**Cost function** (per grid step):
```
cost = 1 + via_penalty(50) + congestion_penalty(8) + bend_penalty(4)
       + power_width_penalty + clearance_violation(×1000)
```

**Grid**: 0.254mm (10 mil) resolution

**Routing order** (priority-driven):
1. Power nets (VCC, GND, VBUS, VSYS) — wider traces, routed first
2. High-speed nets (USB D+/D-, crystal) — shortest path
3. Critical signals (RESET, EN, INT)
4. General signals

**Key functions**:
- `route_nets(model, netlist, pin_matrix, drc, trace_constraints)` — main entry
- `_route_one(src, tgt, ...)` — routes single net on a layer
- `_weighted_a_star(mat, sx, sy, tx, ty, grid_w, grid_h)` — core A* with per-cell cost
- `_build_cost_matrix(...)` — Shapely-aware: pad polygons = impassable, existing traces = costly
- `_net_priority(net)` — classification: 0=power, 1=high-speed, 2=critical, 3=signal
- `_width_for(net, drc, constraints)` — width per net class

**Rip-up & reroute** (lines 394-487):
- After first pass, unrouted nets trigger retry
- Finds shortest existing trace intersecting intended path bbox
- Removes ("rips up") that trace, routes new one, re-routes victim
- Caps at `MAX_RIPUP_PASSES = 3`

**Via placement** (auto, lines 373-390):
- When trace uses B.Cu and pin is SMD (not thru_hole)
- Creates `BoardVia(drill=0.3, diameter=0.6, layers=["F.Cu","B.Cu"])`

### 4.3 Schematic Wire Routing (agent/routing/)

Separate from PCB traces — routes logical connections in schematic view:

- `make_path()` — 5-pass candidate + A* fallback
- Candidates: straight, L-shape, Z-shape, U-shape
- Scoring: `collisions × 10000 + length + bends × 2`
- A* fallback on 1.27mm orthogonal grid with collision awareness

### 4.4 Ratsnest (Airwires)

**Algorithm**: Kruskal's MST (both frontend and backend)

**Frontend** (`_computeClientRatsnest()` in editor_webgl.js:2266-2410):
1. For each net: resolve pad positions
2. Build trace endpoint adjacency (tolerance 0.2mm)
3. Union-Find groups pads connected by copper
4. Kruskal's MST on group representatives (Euclidean distance)
5. Return edges as `{from, to, x1,y1,x2,y2}`

**Backend** (`compute_ratsnest()` in ratsnest.py):
- Same algorithm: Union-Find → group connected pads → Kruskal's MST
- Union-Find with path compression and rank

## PART 7: Constraint Checking (DRC)

### Backend DRC (router2.py: `drc2()`)
1. Trace-to-trace clearance (Shapely polygon intersection)
2. Trace-to-pad clearance (different-net)
3. Minimum trace width
4. Board edge keepout

### Backend DRC (router.py: `drc()` — legacy grid-based)
1. Trace-to-trace clearance (cell-ownership map + 8-neighborhood)
2. Trace-to-component clearance (point-to-bbox distance)
3. Board edge keepout (margin from estimated extents)

### Real-time frontend checking
- `pcbScheduleConstraintCheck()` — debounced 1s, POSTs to `/api/constraint_check`
- Results → `pcbState.findings[]` → rendered as warning icons on components

### Engineering constraint types (8):
POWER_CONNECTIVITY, GROUND_CONNECTIVITY, TOPOLOGY, CLEARANCE, IMPEDANCE, CURRENT_CAPACITY, DECOUPLING, BUS_INTEGRITY

## PART 11: Strengths & Potential Improvements

### Current Strengths
1. **Dual rendering path** — WebGL2 with Canvas2D fallback ensures broad compatibility
2. **Client-side ratsnest** — instant feedback without server round-trip
3. **Weighted A* with rip-up** — sophisticated autorouter with priority-driven net ordering
4. **Shapely-based DRC** — accurate polygon clearance checking
5. **Full undo/redo** — board model snapshot history
6. **Real-time constraint checking** — debounced DRC after every edit
7. **27-layer support** — comprehensive KiCad layer catalog
8. **Axis-locking during routing** — clean H/V trace segments

### Potential Areas for Enhancement
1. **Autorouter not integrated into PCB UI** — `pcb_layout_node` explicitly says "manual routing required"; router2.py exists but isn't wired into the frontend
2. **No push-and-shove routing** — routes can't dynamically reroute around obstacles during manual routing
3. **No differential pair routing** — USB D+/D- need matched-length routing
4. **No copper pour in frontend** — pour.py exists backend but no real-time zone fill visualization
5. **No trace length display during routing** — only shows cumulative length, not per-segment or target length
6. **No fanout assistance** — BGA/via fanout is manual
7. **Single-net routing only** — route_nets() routes one net at a time, no bus/parallel routing

## PART 12: Recommended Implementation Plan

If the goal is to improve/extend the PCB view and trace layout:

### Phase 1: Wire Autorouter into Frontend
- Add "Auto Route" button to PCB toolbar
- On click: serialize boardModel → POST to new `/api/autoroute` endpoint → receive routed traces
- Backend: call `router2.route_nets()` with current model's netlist
- Merge returned traces into boardModel, refresh

### Phase 2: Enhanced Routing UX
- Push-and-shove: when placing a trace near existing traces, show push preview
- Trace length target: show target length from schematic constraints
- Snapping improvements: snap to trace midpoints, existing route angles
- Route preview: show DRC violations live during routing (not just after commit)

### Phase 3: Copper Pour Visualization
- Real-time copper zone fill preview on hover
- Thermal relief visualization for through-hole pads
- Ground plane fill with connectivity verification

### Phase 4: Advanced Routing
- Differential pair routing (matched-length)
- Bus routing (parallel traces)
- Fanout assistance for multi-pin packages
