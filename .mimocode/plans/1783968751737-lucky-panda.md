## 3. Node-by-Node Deep Dive

### 3.1 analyze_node — Subsystem Decomposition

**File**: `agent/nodes/analyze.py`
**LLM Call**: Yes (`ANALYZE_SYSTEM` / `ANALYZE_USER`)

**Algorithm**:
1. LLM call to decompose user prompt into functional subsystems
2. Each subsystem: `{subsystem, function, example_components}`
3. **Keyword fallback**: `_SUBSYSTEM_KEYWORDS` regex maps prompt tokens to subsystem types
4. **Auto-inject**: Adds "Microcontroller" subsystem when sensor/display/wireless detected
5. **User part intent**: `_apply_user_part_intent()` ensures user-named parts appear first

**Key Rules**:
- CRITICAL ELECTRICAL RULE: Voltage mismatch → mandatory "Power Regulation" subsystem
- AVR/ATMEGA CLOCK RULE: 3.3V → 8MHz crystal (not 16MHz)
- EXACT PART NUMBERS: User-specified parts copied verbatim
- ESP32 PROGRAMMING RULE: Include USB-UART bridge subsystem

**State Mutations**: `analysis`

### 3.3 select_node — Component Selection (778 lines, largest file)

**File**: `agent/nodes/select.py`
**LLM Call**: No (uses reranker which calls LLM)

**Algorithm** (13-step pipeline):

1. **Rejection filtering**: Remove candidates matching `rejected_ids` or `rejected_families`
2. **Preserve existing**: Skip subsystems that already have non-passive components
3. **Score and rank** each subsystem:
   - Filter by expected type buckets (13 bucket patterns)
   - Filter by avoid list
   - Call `rank_candidates()` (LLM-based reranker)
   - **Prototyping boost**: +2 score for dev boards in simple designs
   - **User-requested part promotion**: 3-pass search (exact id_str → part-after-prefix → substring)
4. **Selection**: score >= 4 and not "SKIPPED"
5. **Functional-duplicate guard**: Prevents selecting second IC from same library family
6. **Sheet mapping**: Sequential sheet numbering
7. **Final dedup**: Skip duplicate ICs (passives allowed)
8. **Carry forward**: Validator-added components from previous iterations
9. **Supporting component injection** (15 rules):
   - Voltage regulators → 2x input caps + 2x output caps
   - AVR MCUs → RESET pull-up + AREF cap + VCC/AVCC decoupling
   - ESP32 → CP2102N USB-UART bridge + 2x decoupling caps
   - Generic MCU → 2x 0.1uF + 1x 10uF decoupling
   - 1-Wire sensors → 4.7k pull-up
   - LEDs → 330 ohm current-limiting resistor
   - Crystals → 2x 18pF load caps
   - USB-C → 2x 5.1k CC pull-downs + TPD6S300A ESD protection
   - I2C devices → 2x 4.7k pull-ups
   - Transistors → 10k base/gate resistor
10. **Footprint resolution**: RAG → filters → hardcoded defaults (R→0805, C→0805, LED→0805)
11. **Reference designator assignment**: Sheet × 100 numbering

**Type Bucket Patterns** (13 buckets):
```
resistor, capacitor, inductor, diode, led, connector, mcu,
sensor, regulator_switching, regulator_linear, usb_uart, driver, crystal
```

**Prefix Rules** (31 rules):
```
CONNECTOR/USB → J, CAPACITOR → C, RESISTOR → R, INDUCTOR → L,
DIODE/LED → D, TRANSISTOR → Q, REGULATOR/SENSOR/MCU → U,
SWITCH → SW, SPEAKER → LS, RELAY → K, MOTOR → M, BATTERY → BT,
CRYSTAL → Y, FUSE → F
```

**State Mutations**: `selected_components`, `retry_count`

### 3.5 symbol_compatibility_node — Structural Fitness Gate

**File**: `agent/nodes/symbol_compatibility.py` (264 lines)
**LLM Call**: No (purely deterministic)

**3 Structural Checks**:

1. **Pin count ratio**: actual/expected > 10 → error; > 5 + connector + >50 pins → error
2. **Grid-array connector**: >= 16 pads + >= 4 letter prefixes → error
3. **Library prefix vs subsystem**: Sensor must be Sensor_*; MCU must be MCU_*

**Expected Pin Heuristics**:
- connector/header → 4, button/switch/led → 4, sensor → 6
- regulator → 6, display → 16, mcu → 48, usb/uart → 8

**State Mutations**: `rejected_ids`, `validation_errors`

### 3.6 validate_node — BOM Critic (880 lines)

**File**: `agent/nodes/validate.py`
**LLM Call**: Yes (`VALIDATE_SYSTEM` / `VALIDATE_USER`)

**7 Deterministic Pre-checks**:

1. `_check_prompt_integrity()`: MCU family mismatch detection (ESP32 vs ATmega)
2. `_check_module_preference()`: Bare RF ICs that should be modules
3. Auto-replace bare ICs with module variants via RAG search
4. `_enforce_redundancy_repost-LLM enforcement: removes redundant components
5. `_fix_library_prefixes()`: Corrects USB connector prefix errors
6. `_remove_devkit_redundancy()`: Strips components redundant with dev boards
7. Critical pattern scan: catches infrared LED, antenna as resistor, etc.

**LLM Validation** (9 rules):
1. Component TYPE matches SUBSYSTEM function
2. Essential components not MISSING
3. Library prefix matches expected role
4. MODULE AWARENESS: dev boards integrate USB/regulators
5. ATOMIC COMPONENT RULE: never bundle missing components
6. PART FAMILY INTEGRITY: verify MCU family matches prompt
7. BUS/CONNECTOR CHECK: MCU supports required buses
8. WIRELESS-FEATURE CHECK: MCU supports wireless protocol
9. ESP32 PROGRAMMING INTERFACE: USB-UART bridge required

**Post-LLM Processing**:
- Missing component search via RAG
- Footprint resolution
- Ref_des generation
- Stem-matching error filtering
- Placeholder symbol error filtering

**State Mutations**: `selected_components`, `validation_errors`, `rejected_ids`, `rejected_families`

### 3.7 validate_repair_node — Auto-Repair

**File**: `agent/nodes/validate_repair.py` (185 lines)
**LLM Call**: No (uses reranker)

**Algorithm**:
1. Split components into failing (rejected) and passing
2. For each failing component:
   - Get candidates from research_results for matching subsystem
   - Filter by rejected_ids, rejected_families, expected buckets
   - Rerank via `rank_candidates()`
   - If no candidates: search via `search_components()`
   - If replacement found: add to replacements
   - If no replacement: add to `repair_failures` and remove

**State Mutations**: `selected_components`, `retry_count` (+1), `repair_failures`

---

### 3.8 ask_validation_help_node — Human-in-the-Loop

**File**: `agent/nodes/ask_validation_help.py` (70 lines)
**LLM Call**: No

**Algorithm**:
1. Emits `agent:validation_help` with errors/warnings/failures
2. Blocks on `help_event.wait(timeout=300)` (5 min)
3. Actions:
   - `"retry"` → reset retry_count to 1, clear repair_failures
   - `"skip"` → remove failing components
   - `"force"` → clear validation errors
   - `"terminate"` → set error

### 3.12 netlist_node — Netlist Generation (473 lines)

**File**: `agent/nodes/netlist.py`
**LLM Call**: Yes (`NETLIST_BATCH_SYSTEM` / `NETLIST_BATCH_USER` with tools)

**6-Step Algorithm**:

1. **Power/GND pre-assignment** (deterministic):
   - GND pins → "GND" net
   - Power pins → canonical rail name via `power_domains.classify()`
   - PWR_FLAG pins → their named net

2. **Deterministic pin matcher** (4 rules):
   - Temperature sensor VOUT → MCU ADC inputs
   - Screw terminal pins → primary rail + GND
   - Capacitor pins → power rail + GND
   - USB-C receptacle → VBUS, GND, SHIELD, CC1/CC2, SBU1/SBU2

3. **LLM batch processing**:
   - Remaining signal pins in batches (max 24 pins/batch)
   - Formats components with knowledge DB
   - LLM returns JSON with nets + trace_constraints
   - Supports tool calls: PCB calculations + web search

4. **Hallucinated pin resolution** (7-level fallback):
   - Exact pin_num match
   - Exact name match
   - Numeric suffix match
   - Canonical signal name match
   - IO pin fallback
   - Returns None if no match

5. **Bus topology check**: 7 deterministic checks
   - Power isolation, I2C merge, UART cross, same-component short
   - Crystal load caps, power flag required, auto-named nets

6. **PWR_FLAG injection**: For power nets without power_out driver

**State Mutations**: `netlist`, `nets`, `power_pins`, `trace_constraints`, `synthesis_graph`, `selected_components`, `component_ops`, `pin_matrix`

### 3.17 routing_node — Wire Routing (361 lines)

**File**: `agent/nodes/routing.py`
**LLM Call**: No

**Algorithm**:
1. Build component list, restore placements
2. Merge ERC pending connections into working netlist
3. **Pin-Coverage Validation (PCV)**:
   - PCV001: Pin in netlist but no physical wire
   - PCV002: Netlist pin without physical wire
4. **Targeted ERC re-route**: Preserve unaffected traces, route affected nets only
5. **Route traces**: Call `route_traces()` from `agent.routing`
6. **Placement repair + re-route**: If dropped pairs, call `repair_placement_for_routing()`
7. **Wire validation**: Filter by path length, orthogonality, max length (300mm × (1 + erc_retries × 0.5))
8. **Power labels**: Compute directional labels for each power pin
9. Emit `agent:layout_ready` event

**State Mutations**: `component_placements`, `wire_paths`, `power_labels`, `netlist`, `_dropped_pairs`, `_erc_retries`

### 3.20 schematic_audit_node — ERC Audit (265 lines)

**File**: `agent/nodes/schematic_audit.py`
**LLM Call**: No (uses kicad-cli)

**Algorithm**:
1. Regenerate power labels from power_pins + pin_matrix + placements
2. Validate existing traces:
   - Count wired pairs
   - Count missing wires
   - Check bad pin refs
   - Check orphan pins
3. Export `.kicad_sch` via `generate_kicad_sch()`

5. Filter fixable issues
6. ERC-less fallback: synthesize from `_erc_pending_connections`
7. Emit `agent:layout_ready`

**ERC Fixable Types**: `pin_not_connected`, `unconnected_wire_endpoint`, `wire_dangling`, `power_pin_not_driven`

**State Mutations**: `_erc_results`, `_erc_pending_connections`

## 6. Error Handling & Retry Mechanisms

### 6.1 LLM Retry Logic
- `MAX_LLM_RETRIES = 5`
- `MAX_VALIDATION_RETRIES = 3`
- `MAX_BATCH_PINS = 24`
- `_LLM_TOTAL_TIMEOUT = 180s`
- Exponential backoff: 8s → 16s → 32s → 64s + random jitter
- 429 cooldown: 60s + random jitter
- Connection error: auto-restart proxy

### 6.2 Validation Retry Loop
```
validate → validate_repair → validate (max 3 retries)
```
- Tracks `retry_count`, `rejected_ids`, `rejected_families`
- Breaks on: no errors, retries exhausted, user intervention

### 6.3 ERC Repair Loop
```
schematic_audit → schematic_repair → routing → connectivity → schematic_audit (max 3 retries)
```
- Tracks `_erc_retries`, `_erc_pending_connections`, `_erc_affected_nets`
- Breaks on: no fixable errors, error count not decreasing

### 6.4 Human-in-the-Loop
- `ask_validation_help`: After max validation retries (300s timeout)
- `ask_pcb_approval`: Before PCB layout (300s timeout)
- `ask_board_config`: Layer count selection (300s timeout)

## 7. Anti-Prompt-Injection

- `SECURITY_PREAMBLE` prepended to prompts handling external data
- `_sanitize_data()` wraps external data with random boundary tokens
- Zero-width escaping of angle brackets
- Random boundary prevents tag-escaping attacks
