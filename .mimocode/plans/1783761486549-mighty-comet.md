# CircuitBot v2 Architecture Plan

## Vision

CircuitBot stops being "an LLM that writes KiCad files" and becomes an **EDA compiler**: the LLM understands intent, deterministic algorithms own electrical design.

## Principle: v2 is the future, not an integration

The existing subsystem/component pipeline becomes **legacy**. The typed circuit graph becomes the primary source of truth. Old stages are retired gradually, not patched.

### Step 4: Three-Graph Architecture

**New file:** `agent/v2/graph.py`

Separate logical, electrical, and physical concerns.

#### Functional Graph (what the circuit does)

```python
@dataclass
class FunctionalBlock:
    id: str
    function: Function
    description: str

@dataclass
class FunctionalEdge:
    source: FunctionalBlock
    target: FunctionalBlock
    signal_type: str  # "power", "data", "control"

@dataclass
class FunctionalGraph:
    blocks: dict[str, FunctionalBlock]
    edges: list[FunctionalEdge]
```

Example for "ESP32 with button and LED":
```
[USB Power] → [3.3V Regulator] → [ESP32-C3]
                                    ↓         ↓
                              [Button]    [Status LED]
```

#### Electrical Graph (how it's wired)

```python
@dataclass
class ElectricalNode:
    id: str
    component_class: str
    pins: dict[str, PinType]

@dataclass
class ElectricalEdge:
    source_node: str
    source_pin: str
    target_node: str
    target_pin: str
    net_name: str
    voltage: float | None

@dataclass
class ElectricalGraph:
    nodes: dict[str, ElectricalNode]
    edges: list[ElectricalEdge]
    power_domains: dict[str, float]
```

Example:
```
GPIO9 → R1(10k) → 3V3
GPIO9 → SW1 → GND
GPIO2 → R2(330R) → D1(LED) → GND
VBUS → F1(500mA) → VBUS_filtered
VBUS_filtered → U1(AMS1117) → 3V3
```

#### Physical Graph (KiCad symbols + footprints)

```python
@dataclass
class PhysicalComponent:
    ref_des: str
    id_str: str  # "Device:R_Small"
    footprint: str
    pads: list[dict]

@dataclass
class PhysicalNet:
    name: str
    pins: list[str]  # "R1:1", "D1:A"
    wire_path: list[dict] | None

@dataclass
class PhysicalGraph:
    components: dict[str, PhysicalComponent]
    nets: list[PhysicalNet]
```

Graph → nets → KiCad. Zero LLM in this phase.

### Step 6: Pin Mapper

**New file:** `agent/v2/pin_mapper.py`

```python
def electrical_to_netlist(graph: ElectricalGraph) -> list[dict]:
    """Graph edges → KiCad netlist. Deterministic."""
    nets = []
    for edge in graph.edges:
        nets.append({
            "net": edge.net_name,
            "pins": [f"{edge.source_node}:{edge.source_pin}",
                     f"{edge.target_node}:{edge.target_pin}"]
        })
    return nets
```

def generate_netlist(graph: ElectricalGraph) -> dict:

## New Pipeline Flow

```
User Prompt
    │
    ▼
Intent Parser (LLM)
    │  "ESP32 with button and LED"
    ▼
Functional Graph
    │  [MCU] [Button] [Status LED] [USB Power]
    ▼
Pattern Matcher
    │  matches: button_to_gpio, led_status, usb_c_power
    ▼
Engineering Rules
    │  expands: pullups, current limiters, decoupling
    ▼
Electrical Graph
    │  GPIO9→SW1→GND, GPIO9→R10k→3V3, GPIO2→R330→LED→GND
    ▼
Constraint Solver
    │  allocates GPIO, assigns power domains, checks current
    ▼
Pin Mapper
    │  graph edges → KiCad nets
    ▼
ERC Engine
    │  validates electrical correctness
    ▼
ERC Repair (if needed)
    │  fixes graph, not netlist
    ▼
Symbol Resolver
    │  nets → KiCad symbols
    ▼
Footprint Resolver
    │  symbols → footprints
    ▼
Placement
    │  constraint-based layout
    ▼
Routing
    │  A* with DRC
    ▼
DRC
    │  design rule check
    ▼
.kicad_sch / .kicad_pcb
```
