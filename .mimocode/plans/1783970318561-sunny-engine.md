# CircuitBot Datasheet Research - How It Works

## Answer: Yes, It Uses the Web

The datasheet research in CircuitBot is **web-based**. Here's the complete flow:

### Data Flow
```
datasheet_search_node (agent/nodes/datasheet_search.py)
  ↓
deep_search (agent/deep_search/agent.py)
  ↓
tinyfish_search + tinyfish_fetch (agent/deep_search/tools.py)
  ↓
TinyFish API (external web search service)
```

### Primary Source: TinyFish API
- **Search**: Queries the web for datasheets and specifications
- **Fetch**: Downloads and extracts content from datasheet URLs
- **Requires**: `TINYFISH_API_KEY` environment variable in `.env`

### Secondary Sources (Fallback)
1. **KiCad RAG Database** - Local SQLite database with component metadata
   - File: `kicad_rag/store.py` (line 47-61)
   - Contains datasheet URLs and basic info

2. **Knowledge Database** - Pre-built component knowledge
   - File: `agent/knowledge_extractor.py` (line 424-444)
   - Path: `netlist-preprocessing-experiment/knowledge_db.json`

### Caching Mechanisms
- **In-memory cache**: `agent/datasheet.py` (line 23, 31)
  - `_cached_texts`: 500-char summaries
  - `_extended_cache`: 3000-char detailed content
- **Failed URL tracking**: `_KNOWN_FAIL` set to avoid retries

### Failure Handling
When datasheet research fails:
1. Error logged: `"datasheet search failed — {error}"`
2. Graceful degradation continues processing other components
3. Final message reports count: `"Found datasheet information for {N} components"`

### Your Logs Explained
The logs you showed:
```
[THINKING] Searching datasheet for U101 (MCU_Microchip_ATmega:ATmega328P-A)... [THINKING]
    U101 (MCU_Microchip_ATmega:ATmega328P-A): datasheet research complete
```

This indicates:
- The system is calling `tinyfish_search()` for each component
- Search completes (either successfully or with fallback)
- Results are stored in memory for later use

## Files Involved

| File | Purpose |
|---|---|
| `agent/nodes/datasheet_search.py` | Main orchestrator - emits "Searching datasheet" messages |
| `agent/deep_search/tools.py` | TinyFish API wrapper (search + fetch) |
| `agent/deep_search/agent.py` | Deep search logic with LLM synthesis |
| `agent/datasheet.py` | Direct URL downloading + caching |
| `kicad_rag/store.py` | Local KiCad component database |

---

## To Verify Web Search is Working

1. Check `.env` has `TINYFISH_API_KEY` set
2. Run a circuit design
3. Look for actual datasheet content in the logs (not just "research complete")
4. If web search fails, check `agent/deep_search/tools.py` for error messages
