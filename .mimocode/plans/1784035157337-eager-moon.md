# Fix: Blank Web Results in Agent Copilot

## Root Cause

`emit_tool_event()` in `agent/emit_utils.py` generates a **new UUID** on every call. The parent node (`connection_search_node`, `research_node`, `datasheet_search_node`) creates a "running" card, then after `deep_search_parallel` returns, tries to update it to "completed" — but creates a **different card** because the ID is different. The original card stays stuck at "running".

## Fix

### 1. Add `tool_id` parameter to `emit_tool_event`
**File:** `agent/emit_utils.py`

Change `emit_tool_event` to accept an optional `tool_id` parameter. When provided, use it instead of generating a new UUID.

```python
def emit_tool_event(config, title, status="running", summary="", details=None, tool_id=None):
    payload = {
        "id": tool_id or uuid.uuid4().hex[:8],  # reuse ID if provided
        ...
    }
```

### 2. Track tool card ID in all 3 search nodes
**Files:** `agent/nodes/connection_search.py`, `agent/nodes/research.py`, `agent/nodes/datasheet_search.py`

In each node, generate the tool_id ONCE and reuse it for both "running" and "completed" calls:

```python
tool_id = uuid.uuid4().hex[:8]
emit_tool_event(config, "Connection Research", "running", "...", tool_id=tool_id)
# ... do work ...
emit_tool_event(config, "Connection Research", "completed", "...", tool_id=tool_id)
```

### 3. Suppress individual search tool cards in parallel mode
**File:** `agent/deep_search/agent.py`

When `deep_search` runs inside a thread (via `deep_search_parallel`), the individual `emit_tool_call`/`emit_tool_end`/`emit_step` calls create cards that may not render. Pass a flag to suppress them:

- Add `quiet=False` parameter to `deep_search()`
- When `quiet=True`, skip all emit calls (just do the work silently)
- `_deep_search_single` passes `quiet=True` when running in a thread

This keeps the UI clean — only the parent node's tool card is visible.
