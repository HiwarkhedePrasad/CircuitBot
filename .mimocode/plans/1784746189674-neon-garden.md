# Bidirectional Schematic Sync — Implementation Plan

## Goal
Enable CircuitBot to import a `.kicad_sch` file, parse it into its internal model, and sync changes back — so users can edit in KiCad and have CircuitBot incorporate those edits.

## Architecture Overview

```
.kicad_sch file (user edited in KiCad)
        │
        ▼
┌─────────────────────────┐
│  Schematic Importer      │  Parse .kicad_sch → internal model
│  (new: agent/sync/       │  Uses existing sexpr.py parser
│   schematic_importer.py) │
└──────────┬──────────────┘
           │
           ▼
┌─────────────────────────┐
│  Component Matcher       │  5-strategy matching (from circuit-synth)
│  (new: agent/sync/       │  UUID → Ref → Position → Connection → Value
│   sync_strategies.py)    │
└──────────┬──────────────┘
           │
           ▼
┌─────────────────────────┐
│  Diff Engine             │  Compute add/modify/remove plan
│  (new: agent/sync/       │
│   sync_diff.py)          │
└──────────┬──────────────┘
           │
           ▼
┌─────────────────────────┐
│  CircuitBot State Update │  Apply diff to AgentState / design dict
│  (modify: server/routes  │
│   + agent/state.py)      │
└──────────┬──────────────┘
           │
           ▼
┌─────────────────────────┐
│  Re-export .kicad_sch    │  Use existing kicad_export.py
│  (existing)              │
└─────────────────────────┘
```

## What We're Adapting from circuit-synth

The circuit-synth `APISynchronizer` (`src/circuit_synth/kicad/schematic/synchronizer.py`) is tightly coupled to:
- `kicad_sch_api` library (a Python KiCad API wrapper)
- Circuit Synth's `Circuit` object model
- Circuit Synth's `SymbolLibCache`

**We CANNOT directly port it.** Instead, we extract the **algorithm** and adapt to CircuitBot's data model:

| circuit-synth Concept | CircuitBot Equivalent |
|----------------------|----------------------|
| `kicad_sch_api.Schematic` | Parsed S-expression AST (from `sexpr.py`) |
| `SchematicSymbol` | Dict from AST: `{ref, lib_id, value, at, rotation, uuid, properties}` |
| `Circuit.components` | `AgentState.selected_components` (List[ComponentSelection]) |
| `Circuit.nets` | `AgentState.nets` + `AgentState.netlist` |
| `Label` / `GlobalLabel` | Dicts from AST: `{text, at, type, uuid}` |
| `Wire` | Dicts from AST: `{pts: [{x,y}, ...]}` |
| `SymbolLibCache` | Existing `kicad_rag` store + `sexpr_utils.py` |
| `ComponentManager` | Direct AST manipulation + `kicad_export.py` functions |
| `SearchEngine` | In-memory dict lookups on parsed components |
| `NetMatcher` | Wire-tracing on parsed AST |

## Files to Create

### 1. `agent/sync/__init__.py`
Empty init file for the sync package.

### 2. `agent/sync/schematic_importer.py` (~250 lines)
Parses `.kicad_sch` → CircuitBot's internal component/net model.

**Core function:**
```python
def import_schematic(path: str) -> SchematicImport:
    """Parse a .kicad_sch file and return structured data."""
```

**What it extracts:**
- **Components**: From `(symbol ...)` instances — ref, lib_id, value, at, rotation, uuid, properties
- **Lib symbols**: From `(lib_symbols ...)` — pin definitions, graphics
- **Wires**: From `(wire ...)` — endpoint pairs
- **Labels**: From `(label ...)` and `(global_label ...)` — net name, position, type
- **Junctions**: From `(junction ...)`
- **No-connects**: From `(no_connect ...)`
- **Power symbols**: Identified by `#PWR` prefix — ref, value (net name), position
- **Hierarchical sheets**: From `(sheet ...)` — filename, pins, instances

**Parser:** Uses existing `kicad-library-utils/common/sexpr.py:parse_sexp()` — same parser used for PCB import. Returns nested Python lists that we walk with tag-based extraction.

**Output dataclass:**
```python
@dataclass
class SchematicImport:
    components: List[ImportedComponent]    # All symbol instances
    lib_symbols: Dict[str, Any]           # lib_id -> parsed symbol ops
    wires: List[ImportedWire]             # Wire segments
    labels: List[ImportedLabel]           # Local + global labels
    power_symbols: List[ImportedPowerSymbol]  # #PWR symbols
    no_connects: List[ImportedNoConnect]  # No-connect flags
    junctions: List[tuple]                # Junction positions
    sheets: List[ImportedSheet]           # Hierarchical sheets

@dataclass
class ImportedComponent:
    ref: str
    lib_id: str          # e.g. "Device:R"
    value: str
    footprint: str
    x: float
    y: float
    rotation: float
    uuid: str
    in_bom: bool
    on_board: bool
    properties: Dict[str, str]  # All KiCad properties
```

### 3. `agent/sync/sync_strategies.py` (~200 lines)
5-strategy component matching, adapted from circuit-synth's `sync_strategies.py`.

**Strategies (tried in order, first match wins):**

1. **UUIDMatchStrategy** — Match by UUID. Most reliable. CircuitBot generates UUIDs in `kicad_export.py`; if the user hasn't changed them, this is a perfect match.

2. **ReferenceMatchStrategy** — Match by exact reference designator (R1, U1, etc.). Works when user hasn't renamed components.

3. **PositionRenameStrategy** — Match by position + symbol + value + footprint, but different ref. Detects renames (user changed R1→R5 at same location).

4. **ConnectionMatchStrategy** — Match by net topology. If component A has pins connected to VCC, GND, SDA in both Python and KiCad, it's the same component. Uses wire tracing.

5. **ValueFootprintStrategy** — Match by value + footprint as fallback. Least reliable (multiple 10k resistors).

**Key difference from circuit-synth:** We don't have `SearchEngine` objects. Instead, we build in-memory dicts from the parsed AST and the current `AgentState.selected_components`.

### 4. `agent/sync/sync_diff.py` (~150 lines)
Computes the diff between imported schematic and current state.

```python
@dataclass
class SyncDiff:
    components_to_add: List[ImportedComponent]      # In KiCad but not in state
    components_to_remove: List[str]                  # In state but not in KiCad
    components_to_modify: List[ComponentDiff]        # Changed properties
    labels_to_add: List[ImportedLabel]               # New labels
    labels_to_remove: List[ImportedLabel]            # Removed labels
    labels_to_update: List[LabelUpdate]              # Changed net names
    wires_to_add: List[ImportedWire]                 # New wires
    wires_to_remove: List[ImportedWire]              # Removed wires

@dataclass
class ComponentDiff:
    ref: str
    changes: Dict[str, Tuple[Any, Any]]  # field -> (old, new)

@dataclass
class LabelUpdate:
    ref: str
    pin: str
    old_net: str
    new_net: str
```

**Diff logic:**
1. Match components using sync_strategies
2. For matched components: compare value, footprint, position, rotation
3. For unmatched KiCad components: these are user-added → `components_to_add`
4. For unmatched state components: these were removed in KiCad → `components_to_remove`
5. For labels: compare pin→net mapping between wire tracing and state netlist

### 5. `agent/sync/schematic_applier.py` (~200 lines)
Applies the diff to CircuitBot's internal state.

```python
def apply_sync_diff(diff: SyncDiff, design: dict, state: AgentState) -> None:
    """Apply sync diff to the design dict and agent state."""
```

**What it updates:**
- `design['selected_components']` — add/remove/modify components
- `design['nets']` — update net assignments
- `design['netlist']` — update connections
- `design['component_placements']` — update positions
- `design['wire_paths']` — update wire routing
- `design['power_labels']` — update power labels
- `design['net_labels']` — update net labels
- `design['pin_matrix']` — rebuild from lib_symbols

**Re-export trigger:** After applying, the existing `generate_kicad_sch(design)` can re-export the updated schematic.

## Key Design Decisions

### 1. Use existing `sexpr.py` parser (not kicad_sch_api)
Circuit-synth depends on `kicad_sch_api` which is a separate package. CircuitBot already has `kicad-library-utils/common/sexpr.py` — a battle-tested parser used for PCB import. We use the same parser for schematic import, keeping dependencies minimal.

### 2. Parse → diff → re-export (not AST modification)
Circuit-synth modifies the `kicad_sch_api` AST in-place. We take a simpler approach: parse → compute diff → apply to AgentState → re-export using existing `generate_kicad_sch()`. This reuses the proven export path and avoids fragile AST surgery.

### 3. Wire tracing for connection matching
For the ConnectionMatchStrategy, we trace wires to determine which pins are connected. This is simpler than circuit-synth's `ConnectionTracer` because we only need boolean connectivity (are these two pins on the same net?), not full routing information.

### 4. Preserve user-added components
When importing, components in the `.kicad_sch` that don't match any state component are treated as user-added. They get added to the state. Components in state that don't match any KiCad component are flagged as removed (with user confirmation).

## Verification

1. **Unit test:** Create `tests/test_schematic_import.py`
   - Parse a sample `.kicad_sch` → verify component count, ref list, net list
   - Round-trip: export → import → compare

2. **Integration test:** 
   - Generate a circuit via agent → export .kicad_sch
   - Modify in KiCad (change R1 value from 10k to 4.7k, add R99)
   - Import modified .kicad_sch → verify R1 value changed, R99 added

3. **Manual test:**
   - Run server, generate a circuit
   - Download .kicad_sch, open in KiCad
   - Move a component, change a value, add a wire
   - Upload modified .kicad_sch via "Import" button
   - Verify CircuitBot shows the changes
