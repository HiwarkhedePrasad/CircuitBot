# Fix RAG Component Retrieval Pipeline

## Root Cause

The `search_components` function in `agent/tools.py:189` treats the pipe-separated `library_filter` as a **single literal prefix** instead of splitting on `|`. This means a filter like `"Connector_USB|Connector"` becomes `"Connector_USB|Connector:"` which matches **nothing** in the KiCad symbol index.

When the filter returns zero results, `research.py` falls back to **unfiltered** BM25 search, which returns broad matches including MCUs for queries like "Power Input".

## Failure Chain

```
LLM analysis produces: {"subsystem": "Power Input", "library_filter": "Connector_USB|Connector"}
  → research.py calls search_components("Power Input", library_filter="Connector_USB|Connector")
    → tools.py does: r.id_str.startswith("Connector_USB|Connector:") → ALL filtered out (matches nothing)
      → research.py fallback: search_components("Power Input") [no filter]
        → BM25 query: "power" OR "input"* → returns MCUs, regulators, anything mentioning "power"
          → select.py gets MCU candidates for "Power Input" subsystem → skips it (score=0)
```

## Fix Plan

### Fix 1: `agent/tools.py` — Split pipe-separated library_filter (CRITICAL)

**File**: `agent/tools.py:187-189`

**Current (broken)**:
```python
if library_filter:
    results = [r for r in results
               if r.id_str.startswith(library_filter + ":")]
```

**Fixed**:
```python
if library_filter:
    filter_prefixes = [f.strip() + ":" for f in library_filter.split("|")]
    results = [r for r in results
               if any(r.id_str.startswith(p) for p in filter_prefixes)]
```

This is the **single highest-impact fix**. The library_filter values from templates and `get_library_filter()` are already correct — they just don't get applied properly.

### Fix 2: `agent/nodes/research.py` — Remove `or deduped` fallback (line 82)

**File**: `agent/nodes/research.py:82`

**Current**:
```python
deduped = [r for r in deduped if any(r["id_str"].startswith(p + ":") for p in filter_patterns)] or deduped
```

**Fixed**:
```python
deduped = [r for r in deduped if any(r["id_str"].startswith(p + ":") for p in filter_patterns)]
```

The `or deduped` at the end means: if the post-hoc filter removes ALL results, fall back to unfiltered. This defeats the purpose of the filter. Remove it — if no results match the filter, return empty and let the subsystem be skipped.

### Fix 3: `agent/nodes/research.py` — Log when filter returns empty (line 62-70)

The fallback at lines 62-70 searches without filter when the filtered search returns nothing. After Fix 1, this should rarely trigger. But if it does, log a warning so it's visible:

```python
if not results and library_filter:
    _emit(config, "agent:log", {
        "message": f"  WARNING: No components found for '{name}' with filter '{library_filter}'"
    })
```

Keep the fallback search as-is (it's needed when the RAG index genuinely doesn't have the component type), but the log makes it visible.

### Fix 4: `agent/nodes/select.py` — Add missing subsystem expectation hints

**File**: `agent/nodes/select.py:49-59`

Add entry for "power input" → connector:

```python
("power input", {"connector"}),
```

This ensures that even if RAG returns mixed candidates, the type filter correctly expects connectors for "Power Input" subsystems.
