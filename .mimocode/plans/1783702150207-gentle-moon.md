# Fix: Airwire (Suggest Line) Should Start From Trace Endpoint, Not Cursor

## Problem

When routing a trace, the airwire (suggest line) for the routed net is currently redirected from the **original starting pad** to the **cursor position**. This means the suggest line follows the mouse cursor everywhere, rather than showing the connection from where the trace actually ends.

## Current Behavior (editor_webgl.js:950-994)

In `_drawAirwiresCanvas`:
- `routeSourceKey` = the original pad key where routing started (e.g., `"R1:1"`)
- `routeCursor` = current mouse position in world coords
- Any airwire whose `from` or `to` matches `routeSourceKey` gets its endpoint replaced with `routeCursor`

So the suggest line goes: **cursor → unconnected pad**

## Desired Behavior

The suggest line should start from the **last placed point** of the trace being drawn (`routePoints[routePoints.length - 1]`), not from the cursor.

So the suggest line goes: **end of drawn trace → unconnected pad**

This is more useful because:
1. As you add segments, the airwire updates to show from the actual trace endpoint
2. It visually shows "this net still needs to be connected from here"
3. The cursor preview line (yellow `#fff1a8` stroke at line 732) already shows the cursor-to-last-point preview, so we don't need the airwire to duplicate that
